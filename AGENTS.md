# AGENTS.md — hdots engine conventions

The dotfiles backend engine at `$HOME/.config/hdots` (the *source of truth*; runtime
copy is staged under `/tmp`). `~/.config/hypr` and `~/.config/quickshell` are symlinks
into it. Not a git repo — edit carefully, no rollback. Separate project from the
quickshell shell itself (`quickshell/AGENTS.md` + `quickshell/ROADMAP.md` cover that).

## Hard rules

- **Efficiency first, not bash purity.** Bash built-ins (parameter expansion, `[[ ]]`,
  `case`, `read -r` + `IFS`, arrays, `(( ))`, `< file`, `echo x > file`) are preferred
  in hot/tight loops because `fork`+`exec` churn is the real cost — e.g. `get_bat`,
  `qpid` (pure `/proc/[0-9]*` scan), `battery-stat`. But an external binary is fine —
  even preferred — when it's genuinely faster for the job (bulk `awk`/`lsblk` data
  munging in `system-stat`, `rsync` backup, `unzip`/`tar`). Speed wins over dogma.
- **No existence checks; source, don't fork.** `hypr_init_logic` guarantees that
  `$states/themes`, `$states/scheme_<cm>` and the `$states2` palette files exist
  before the shell runs, so the runtime engine (`fetch_color_scheme`,
  `theme_save_hex`, `qs-themes`, `hypr_init_logic`) performs NO existence tests —
  `[[ -f ]]`/`[[ -d ]]`/`ls`/`find` are banned in the hot path. Read with
  `$(<file)`/`read -r`, write with `echo x > file` (never `cat`, never `touch`),
  include helpers with `.` (never `bash script` — no forks), and use `IFS= read -r`
  on TAB-split theme lines. If a file can be missing, the fix is to make
  `hypr_init_logic` (or `gen_flags_master`) create it — not to add a check.
- **`luajit` = heavy-lifting engine only.** Use it for what bash can't do fast: shade
  generation (`gen_hex_shades.lua`), wallpaper accent extraction (native C
  `hypr_bin/lib/color_engine_native`, stb_image via FFI `libstb.so`), kernel-level file
  copy (`sources/functions.lua` → `copy_file_range`), thumbnail generation
  (`generate_thumbs.lua`), Hyprland config generation (`*_config_gen`). Bash stays the
  default; lua/C only where bash would be slow or awkward.
- **Minimal SSD writes.** Everything staging, generated config, and runtime state lives
  under `/tmp` (`$hypr_base`, `/tmp/$USER_hypr_conf`, `/tmp/hypr_global`) — tmpfs/RAM,
  not disk. `main_logic` does `rm -rf` + `mkdir -p` + `cp -r … &` + `wait` batch copies.
  `sync_first` copies `states/` → `/tmp`. chmod 700 everything under `$hypr_conf`.
- **Generated files are sacred.** Files generated at boot say `-- Generated by … do not
  edit` (e.g. `hyprland.lua`). Put changes in `overrides.lua` / the source template in
  `sources/`, never in the generated output.
- **Thin dispatcher pattern.** A `hypr_bin` tool is a tiny `case` wrapper that sources
  a `sources/helpers/<name>_body` (the real function library) and dispatches:
  `. $hypr_sources/helpers/audio_body` then `case $1 in vol) case $2 in up) vol_up_func …`.
  Bodies hold logic; bins never carry logic.
- **State via files, not vars.** Runtime state is persisted with `echo x > file` and read
  with `$(<file)` so subshells/backgrounded jobs/waybar modules share it without exports.

## Engine flow — starts at `hypr_init`

- `hypr_bin/hypr_init` (one-liner) → sources `sources/helpers/hypr_init_logic`, the
  single boot pipeline:
  root-gate → `setup_dirs_master` → `hyprland_main_config_gen` → one-time
  `mako_dummy_conf_gen` → `expand_gen_body` → `gen_flags_master` (fills missing
  `states/*` defaults) → `sync_first` → `hex_to_alpha` → theme acc defaults
  (`fetch_color_scheme` reads the master `$states/themes` — the legacy
  `hdots_d`/`hdots_l` palettes now live there as themes — and seeds
  `states2/{fg,fg2,fg3,bg,bg2,bg3,hover,border,acc,sfg,success,warning,danger,info}`)
  → caps-lock
  path/state → default browser → audio state (`states2/vol*`, `mic*`, `audio_id`) →
  `create_hex_individual_files` → `hypr_init_run_once` (distro detect from
  `/etc/os-release` → `states2/distro`) → desktop-launcher `expand_gen` → symlink pairs
  (`symlink_dirs`/`symlink_files`/`target_point`/`link_it_defs`/`point_to_contents`) →
  `hypr_init_gen_array` → `shaders_gen` → rofi gen → `luajit generate_thumbs.lua` →
  gnome-keyring + `dbus-update-activation-environment` → battery detect →
  matugen `config.toml`/`generic.ini` → `gen_alpha_sample` + `hypr_idle_lock_conf_gen`
  → hypr-theme dark/light-alt dirs + index.theme → `gen_custom_acc_files` → states2
  mode/channel/launcher writes → `hyprctl plugin load scrolloverview.so` →
  `theme_main restore` → thunar daemon kick + window-count quirk → sleep 10 →
  `run_inside_loop` + `watch_dog` → `gen_scheme_cache` → `hyprsunset_main restore` →
  keybinds cache → chmod 700.
- **Launch variants** (`launch_bins/`):
  - `prelaunch_hypr` — Hyprland entry (fired from generated `hyprland.lua` via
    `hl.on("hyprland.start")`). Sources `prelaunch_body`, calls `launch_final_func`.
  - `prelaunch` — same + `hyprctl eval "hl.config({ cursor = { inactive_timeout = 0.01 } })"`
    then `launch_final_func` + explicit `hypr_init`.
  - `prelaunch_body` — defines `main_logic` (staging rm/mkdir/cp),
    `splash_func` (launches quickshell `Splash.qml`, signals via
    `/tmp/qs_config_loaded_$$`, 5s timeout), and `launch_final_func` (gtk-theme →
    `mode_init=d|l`, `states2/sm=${s}${m}`, splash, `main_logic`, then sources
    `hypr_init_logic`).
  - `env` / `niri_env` — default env (`hypr_base=/tmp`, `default_terminal=alacritty`,
    `default_launcher=rofi`, `default_file_manager=thunar`, `hypr_auto_launch=1`) +
    all path vars; creates + sources `~/env_override` for user overrides.

## `hypr_bin` tool inventory (74 bins + `lib/` + `menu/`)

- **Dispatch wrappers** (thin `case` over `helpers/*_body`): `audio_main`, `blur_main`,
  `opacity_main`, `shadow_main`, `shader_main`, `hyprsunset_main`, `waybar_main`.
  (`theme_main` — switch/dark/light/restore/reapply/list/apply — moved to the
  quickshell `scripts/theme_main` + `theme_main_body`, 2026-08.) Brightness is NOT in hypr_bin
  anymore — `brightness_main` (quickshell `scripts/`, symlinked on `$PATH`) absorbed
  the old `bl_main` + `bl_gamma_body` (gamma-at-max tweak, lazy 1% steps, bar OSD
  IPC), which were deleted.
- **rofi menus** — `master-menu` hub execs into `menu/<feature>/*` trees; `..` back-nav
  convention; single rofi instance via `rofi_id` + `qpid` (kill/relaunch dance);
  per-menu `.rasi` theme staged to `states2/rofi_*.rasi`; `rofi_source.rasi` import.
  `show_keybinds` reads `$hypr_cache/keybinds` (parsed from `keybinds.lua` comments).
- **Floating terminal sliders** — `vol_slider`, `bl_slider`: raw `read -rsn1` key loop
  (no CPU spin), `stty`/`tput` ansi UI, millisecond-flush throttle via
  `date +%s%3N`, state diffed against `prev_*` before writing files, flushed only when
  changed. `launch_it` wraps them with `alacritty --class floating-script`.
- **Waybar JSON modules** — `battery-stat`, `system-stat`, `custom_clock` emit
  `{"text":…,"tooltip":…,"class":…}`. `module_reload <sig>` =
  `pkill -RTMIN+$(<states2/sig) waybar`; waybar triggers on `sig_*` files in `states2`.
- **State readers/writers** — everything `$(<file)`/`echo > file`, per-channel suffixes
  `_d/_l/_n` (dark/light/normal), e.g. `blur-menu*`, `shadow-menu*`, `opacity-*`,
  **Channel is the key**: the active channel (`$states2/s`, `n`|`d`|`l`) suffixes
  the state file, so `custom_acc_<channel>` = `custom_acc_n`/`custom_acc_d`/`custom_acc_l`.
  `n` = global (one value shared by both themes), `d` = dark only, `l` = light only.
  Channel picks the suffix; `$states2/m` always tracks the ACTIVE theme (`d`|`l`):
  channel `l` ⇒ mode `l`, channel `d` ⇒ mode `d`, channel `n` ⇒ mode is `l` or `d`
  (active theme) while the file stays `*_n`.  `$states2/sm` is the state+mode
  concatenated into one file (strictly one of `dd`, `ll`, `nd`, `nl` (nothing else)) so callers do
  `sm=$(<$states2/sm); s=${sm:0:1}; m=${sm: -1}`; these flags are set by
  `save_flags_func` (in the quickshell `scripts/theme_main_body`) on every
  theme/mode/channel switch. See quickshell AGENTS.md for the full model.
  `theme_menu`, `set_wall` (→ `awww_init`). `general_main` writes
  `configs/general.lua` as a Lua literal consumed by Hyprland's `hl.config`.
- **Special** — `chrome_link_toggle` (swap profile → `/tmp/google_chrome_temp`),
  `power-menu` (uptime from `states2/uptime`, loginctl/systemctl actions),
  `record_capture`, `win_switcher` (dynamic rofi window grid), `extract_here`
  (AppImage/tar/zip), `game_mode_toggle` (hyprctl batch), `hypridle_restart`,
  `set_cpu_freqs`, `battery-stat`/`get_bat`, `thunar-*-symlink`.
- **`lib/`** — `color_engine.c` → `color_engine_native` (C, stb_image: modes `d`ominant
  / `s`aturated / `f`ast pick from wallpaper), `libstb.so` (stb_image+w+r FFI target for
  lua), `stb_wrapper.c`.
- **`menu/`** — `accent_menu`, `battery_stat`, `clipboard_manager`, `fonts`, `general`
  (gaps/borders/rounding), `glyphs`, `margin_ratio`, `notification_toggles`,
  `padding_margin`, `power_tune`, `record_capture`, `restore_defaults`, `system_stat`,
  `wall_menu`, `waybar_chooser*`, `waybar_style_chooser`.
- **Stale / superseded — do NOT touch.** Several bins + helpers are leftovers from the
  pre-quickshell shell and are kept on disk intentionally. This includes the waybar
  JSON modules (`battery-stat`, `system-stat`, `custom_clock`, `waybar_main`,
  `module_reload`) and the rofi splash / center-pop menus (`appmenu`, `startmenu`,
  `rofi-toggle`, `win_switcher`, `master-menu` + `menu/` trees, `splash_init`, `pop`,
  `power-menu` (slated for deletion), etc.). The quickshell pill, control center,
  power panel, launcher and splash have superseded them; some are still referenced
  from waybar configs / keybind docs. **Ignore them: don't refactor, delete, fix, or
  route new features through them — leave as-is.**
- **`master-menu` + `menu/` tree stays as-is.** The rofi `master-menu` and all its
  submenus (`general`, `wall_menu`, `theme_menu`, `fonts`, `accent_menu`, `blur-menu`,
  `shadow-menu`, `opacity-menu`, `shader-saturation-menu`, `hyprsunset-menu`,
  `restore_defaults`, `channel_switcher`, `record_capture`, `notification_toggles`,
  `clipboard_manager`, `power_tune`, `show_keybinds`) are **intentionally NOT ported to
  the quickshell settings app** and are kept on disk verbatim. Do not port, refactor,
  delete, "fix", or route new features through them — they are the frozen legacy surface.

- `loop` → `before_loop` (sleep 1, enable `sysrq`, `unmounter_status=1`) → tight loop:
  `sleep $fire_delay`, only runs `during_loop` when `fire_count` is non-zero.
- `during_loop` — decrements `fire_count`, `set_cpu_freqs` (if `flag_cpu`), drains
  `disks_to_unmount_batch/*` (per-partition `umount`/`umount -l`, whole-disk scan via
  awk on `/proc/mounts`), chmod 777 the fire files.
- `on_udev_trigger` — udev power-event entry, debounced, runs `battery_stats_reload`.
- `main_body` — power-plan apply: reads `ADP*`/`ucsi-source-psy-*` online, AC vs battery
  plan → writes `scaling_max_freq`/`scaling_governor`/`power_dpm_*` via `sudo tee`.
- `run_inside_loop` — ensures hypridle/thunar/alacritty/cliphist-store (both text +
  image DB) are alive via `qpid` + `hl.dsp.exec_cmd`. `user_loop` re-runs it every 30s.
- `watch_dog` — self-restarting supervisor (PID files in `states2`) that relaunches
  `user_loop` when it dies. `loop_is_running` written as a heartbeat.

## State system

- `$states` (`/tmp/$USER_hypr_conf/states`, synced from `hdots/states` by `sync_first`)
  — persistent per-channel flags: accents (`acc_*`), `acc_alpha_*`, `border_alpha_*`,
  `bg_alpha_*`, blur/shadow/opacity/waybar settings, `scheme_<ch><mode>`,
  `current_wall_<ch>`, `clock_state_*`, `start_logo_*`, `power_*`. Source of truth is
  `hdots/states/`; never edit the synced copy.
- `$states2` (`states_2`) — runtime/boot state, regenerated every launch: `cm`
  (channel+mode), `channel`, `s_dummy`, `mode`, `mode_init`, `acc_changed`,
  `acc_dd`/`acc_nd`…, `vol`/`mic`/`max_*`/`audio_id`, `uptime`, `battery_found`,
  `distro`/`distro_name`, `caps_lock_*`, `rofi_id`, `sig_*` (waybar signals),
  `h_l`, `system_stat_glyph`, `cur_font`/`cur_theme`/`cur_icon`/`cur_cursor`,
  `use_theme_colors`, `launcher`, `mode_string`/`channel_string`.
- `$hypr_global` (`/tmp/hypr_global`) — global daemon/shared state: `qpid`,
  `states/`, `fire_count`, `flag_cpu`, `flag_disk_unmount`, `unmounter_status`,
  `disks_to_unmount_batch/`, `rofi_relaunch_counter`, `user`, scripts from
  `scripts_global/` (executable copies).

## Helpers (`sources/helpers/`) — key building blocks

- `expand_gen` (`expand_gen_body`) — heredoc template expander:
  `eval "cat <<EOF $(<src) EOF" > out`; used for every generated config.
- `link_it_defs` — `link_it_file_func`/`link_it_dir_func`: back up existing target to
  `*.bak.$rnd`, `ln -s` source→target, idempotent via `-ef`.
- `point_to_contents` / `point_to_contents_rel` — rel-symlink every entry of right dir
  into left dir (theme alt-dirs, thumbs).
- `qpid` (from `source_run/`) — pure-bash pid lookup scanning `/proc/[0-9]*/comm`.
- `*_body` files — the real function libraries for the dispatch wrappers (`audio_body`,
  `bl_gamma_body`, `blur_body`, `opacity_body`, `shadow_body`, `shader_body`,
  `hyprsunset_body`, `waybar_body`, `power_body`, `hypridle_*`; the theme
  apply/switch funcs formerly in `theme_main_body` moved into the quickshell
  `scripts/theme_main_body`, 2026-08).
- `hex_to_alpha`, `hex_to_rgba`, `get_sfg`, `contrast_check*`, `hex_set_bright`,
  `gen_hex_shades.lua`, `gen_alpha_sample`, `gen_custom_acc_files`, `init_*_hex`,
  `init_custom_accent`, `fetch_color_scheme`, `pull_colors_val`, `color_pick_logic`
  — the accent/color engine.
- `pop`, `dmenu_tiny`, `brace_and_sep`, `splash_init`, `link_it_defs`, `hypr_init_logic`,
  `hypr_init_run_once`, `hyprland_main_config_gen`, `hypr_idle_lock_conf_gen`,
  `hyprsunset_body`, `create_dummy_configs`, `gen_launcher_cache*`, `gen_rofi_configs`,
  `gen_scheme_cache`, `gen_gtk_css_*`, `regen_*`.
- Lua (heavy lifting): `generate_thumbs.lua` (stb FFI → `/home/$USER/.cache/thumbnails/
  hdots/wall_thumbs`), `gen_hex_shades.lua` (hex → shade ramp), `functions.lua`
  (FFI copy_file_range copy), `color_engine.lua` (native C binding).

## Suggested improvements (robustness only — speed is already maxed)

- `battery-stat` reads `voltage_now`/`power_now` unconditionally — they can read 0 on
  AC/DC transitions → integer-div by zero → bad waybar JSON. Guard with a 0/`-e` check.
- `master-menu` uses `SCRIPT_DIR=${0%/*}` — fine via PATH-resolved `$0`, but prefer
  `BASH_SOURCE[0]` (already used in `menu/*`) if it could ever be invoked by relative path.
